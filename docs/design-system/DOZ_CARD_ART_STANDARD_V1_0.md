# DOZ Card Art Standard v1.0 — 홈페이지 앱 카드 이미지 제작 규격

- 상태: **실무용 1차 기준안 · 카드별 새 아트 생성 전 검수 필요**
- 기준일: 2026-11-08
- 연계: `DOZ_UI_SYSTEM_V1_0.md`, `HOMEPAGE_R54_HERO_REVISION_SPEC.md`
- 변경 보호: 기존 DZlog A(단이)·그리글 C v3·MY LOCK E **승인/선택 원본을 덮어쓰지 않는다**. 기존 앱 아이콘은 프로젝트의 **공식 원본 바이너리**를 사용한다.

## 1. 시각적 마스터 방향

**공통 장면:** 따뜻한 아침 자연광이 들어오는 한 공간의 공방·작은 정원/책상. 아이보리·크림·연녹색을 기본으로 종이·나무·부드러운 섬유를 주로 사용. 데이지/작은 잎사귀 등의 장식은 앱 기능보다 눈에 띄지 않을 만큼 절제한다. 과장된 장난감 3D·심한 광택·앱마다 별도 판타지 세계를 금지한다.

**공통성**은 색온도, 광원 방향(좌상단 자연광), 질감, 카메라 렌즈/원근감, 타이포 위계, 바깥 여백, 모서리, 정보 밀도를 통일해서 만든다. **차별성**은 앱의 주요 기능 데모 장면과 제한된 보조 포인트 컬러로 만든다.

### 공통 규격 (모든 카드)

| 요소 | v1.0 기준 |
|---|---|
| 광원 | 좌상단에서 오른쪽 아래로 부드럽게 들어오는 자연광 |
| 색온도 | 따뜻한 크림/아이보리 + 저채도 녹색, 과도한 노란색/형광색 금지 |
| 재질 | 종이·우드·니트·무광 유리/세라믹, 균일한 자연 질감 |
| 밀도 | 핵심 기능 1개, 주 소품 1~2종, 보조 꽃/잎 최소화 |
| 정보 위계 | 공식 앱 아이콘 → 앱명 → 짧은 설명 → 대표 기능 장면 |
| 타이포 | `Noto Sans KR` 기반, 카드명 굵게; 설명 1~2행만 |
| 바깥 안전영역 | 카드 가장자리에서 최소 6% (텍스트/아이콘 주요부) |
| 모서리 | 사이트 카드 외곽 radius 24px와 시각 일치 |
| 색상 차별화 | 기능 장면에만 앱별 포인트색, 공통 크림 배경 유지 |
| 재사용 | 같은 배경 스타일·조명·기본 레이아웃·아이콘 높이 비율 |

## 2. 카드별 정보 구조 (틀은 공유, 장면만 다름)

- **DZlog A (대표/세로형)**: 좌상단 공식 앱 아이콘/앱명/한 줄 핵심 설명. 주요 시각물은 사진·기록 메타데이터가 보이는 실사용 느낌의 카메라/기록 프레임. 단이는 기존 승인된 캐릭터·사진 사용(새로 다른 동물을 생성하지 않음). 안정적이고 가장 실용적인 카드.
- **그리글 C v3 (가로형)**: 동일 정보 위계와 배경 조명. **슬림한 실제 비율의 바형 스마트폰**에 사용자 제공 실제 키보드 테스트 화면을 정확히 합성. 제스처 가이드·숫자열·하단 기능키를 임의 문자로 다시 생성 금지. 태블릿형 화면/독립 터치패드 같은 큰 패널 금지.
- **MY LOCK E (가로형)**: 동일 정보 위계와 질감. 공식 아이콘 + 실제 잠금화면 제품 정체성이 보이는 폰 목업. 라벤더/파스텔 포인트는 기능 장면에만 제한, 배경 전체를 다른 세계관으로 전환하지 않음.

## 3. 최종 출력 규격 — 사이트 '슬롯'을 기준으로 생성

**최종 카드의 픽셀 비율은 일단 슬롯/화면 레이아웃 확정 후 결정.** 현행 파일은 다음과 같이 서로 비율이 다르며, 이것이 웹 카드에서 어색한 여백의 직접 원인이다.

| 현재 자산 | 원본 해상도 | 가로/세로 비율 | 상태 |
|---|---:|---:|---|
| DZlog A | 710×866 | 0.820 | 보존 |
| 그리글 C v3 | 1672×941 | 1.777 | 보존 |
| MY LOCK E | 839×390 | 2.151 | 보존 |

**통일형 리디자인의 표준 슬롯 후보:** DZlog 세로 `~0.82:1`, 우측 그리글·MY LOCK 가로는 **동일 슬롯 비율**(예: 약 `1.75:1`)로 설계. 두 가로 카드의 바깥 높이를 동일하게 맞추되 내부 장면을 해당 슬롯에 맞게 다시 구성한다. 최종 수치는 실제 R5.4 히어로 QA 후 동결. 예시 출력 마스터는 웹 슬롯의 **2–3배 해상도**, 웹 파생 WebP와 원본 PNG를 모두 별도 저장.

- 기존 승인 MY LOCK 이미지를 1.75:1 슬롯에 맞추려고 이미지를 단순 늘리거나 잘라서는 안 됨. 새 버전 아트로 만들 때 **원본에 없는 배경 부분을 채워 안전영역을 확장하거나 레이아웃을 재설계**하여 사용자가 확인한 후 교체.
- 배경 재생성이 필요할 경우에도 **앱 아이콘과 실제 화면**은 먼저 제외한 **깨끗한 배경/목업 아트만 생성**한다.

## 4. 제작 파이프라인 — 반드시 단계 구분

1. **브리프**: 앱 목적, 1문장 설명, 슬롯 비율, 포인트색, 꼭 보여줄 실제 UI/캐릭터, 금지요소를 카드 단독으로 확인.
2. **스타일 기준 참조**: 기존 DOZ 카드 마스터와 공통 컬러·조명·소품 밀도 준수. 이미지 생성은 배경·목업·질감 등 **창작 아트 부분**에만 적용.
3. **공식 자료 확보**: GitHub/원본 보관소에서 정식 앱 아이콘 파일과 앱 스크린샷을 수집하고 SHA-256 및 파일 경로 기록.
4. **합성**: 공식 아이콘은 원본 픽셀/형태 변경 없이 정확한 크기로 배치, UI 캡처는 화면의 원근·모서리·광원에 맞게 투영. 유리면 안쪽 외의 목업을 임의로 바꾸지 않음.
5. **텍스트**: 앱명/설명은 가능하면 후편집에서 실제 폰트로 벡터/래스터 조판. 이미지 생성기가 한글 글자를 제멋대로 쓰게 두지 않음.
6. **디자인 QA**: 한 장씩(기존 요구대로 3카드 합본 시안 불필요) 앱별 검수하고, 서로의 디자인 일관성은 체크리스트/값 비교로 검증.
7. **기술 QA**: 100% 확대·실제 웹 슬롯 크기·모바일 크기 점검. 이미지 왜곡·오탈자·공식 아이콘 사용·앱 UI 정확도·파일 해시 점검.
8. **승인/보관**: 원본/중간/최종 버전 별도 폴더 저장; 최종 승인 상태와 기준 버전 기록. 승인 전 운영에 적용하지 않음.

## 5. 표준 프롬프트 골격 (이미지 생성 대상: 배경/목업 아트만)

> 두도지공방 앱 소개 카드의 **배경 아트와 목업 소품만** 제작한다. 따뜻한 아침 자연광이 좌상단에서 들어오는 하나의 정돈된 공방/작은 정원 공간. 크림·아이보리·세이지 계열, 무광 우드/종이/니트 질감, 잔잔한 데이지와 잎사귀 소품을 절제하여 배치한다. 고급스럽지만 과하게 광택이 나는 3D 장난감 느낌은 피한다. 앱의 대표 기능을 설명할 스마트폰 또는 기록 프레임 **빈 목업 공간**을 마련하고, 좌상단에는 공식 앱 아이콘/앱명/설명 조판용 **안전영역을 비워둔다**. 한글 문구나 앱 아이콘, 임의 UI를 그리지 않는다. 제작 슬롯: [가로세로 비율], 장면: [앱별 대표 기능], 포인트색: [앱별 1종].

**앱별 추가문**
- DZlog: 기록용 사진 프레임과 깔끔한 데이터 기록 요소가 들어갈 위치 제공. 단이 공식 이미지 삽입 안전영역 마련.
- 그리글: 가로 카드 오른쪽에 **9:19.5에 가까운 슬림 바형 스마트폰** 목업. 내부는 실제 키보드 캡처를 나중에 원근 합성할 수 있도록 깨끗한 빈 스크린.
- MY LOCK: 세로형 스마트폰 잠금 화면용 빈 스크린 및 소량의 장식 포인트. 라벤더는 보조 색상만.

## 6. 금지/실패 판정

- 공식 앱 아이콘의 이미지 생성·벡터 재해석·색상 교체/왜곡.
- 사용자가 제공한 캐릭터 마스터와 다른 신규 캐릭터 생성.
- 실제 앱 UI라고 하면서 가짜 글자·키 배열·임의 앱 화면을 그림으로 재현.
- DZlog/그리글/MY LOCK의 조명·재질·글꼴·장식 밀도가 제각각인 채 승인.
- 폰 비율을 넓혀 태블릿처럼 보이게 하거나 기존 폰 위에 별도 패널을 얹은 형태.
- 가장자리 텍스트·폰·꽃/장식의 무분별한 크롭, `object-fit:fill`로 왜곡.
- 기존 최종 승인 파일을 이름 그대로 덮어쓰기.
