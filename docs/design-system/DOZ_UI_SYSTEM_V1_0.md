- 상태: **실무용 1차 기준안 · 시각 검수 전 (Draft)**
- 기준일: 2026-11-08
- 적용 범위: 두도지공방 홈페이지 R5.4 비운영 프리뷰 및 향후 앱 소개/상세 페이지
- 상위 원칙: **기존 R5.3 운영 유지, 기존 승인 이미지·공식 아이콘 원본 보존, 비운영 PR에서 검수 후 적용**
- 연결 작업: GitHub Issue #6 / Draft PR #7 (`feat/homepage-r54-static-cards-20261104`)

## 1. 디자인 목표와 역할

**따뜻한 공방 감성 + 정돈된 디지털 UI**. 자연광·식물·나무 책상의 기존 사진 분위기는 유지하되, 홈페이지 내부 UI 요소(텍스트·카드 외곽·버튼·탭·간격·색상·상태)를 공통 규칙으로 관리한다. 앱별 홍보 카드의 이미지 아트는 별도 `DOZ_CARD_ART_STANDARD_V1_0.md`에 따른다.

**계층**: (1) 브랜드/의미 토큰 → (2) 타이포·간격·레이아웃 → (3) 공통 컴포넌트 → (4) 페이지별 배치. 이미지 안의 텍스트·앱 UI는 사이트 CSS와 별개이며, 편집할 때는 카드 제작 규격을 따른다.

## 2. 공통 디자인 토큰

### 2.1 색상 — 현재 저장소 `public/styles/tokens.css`의 기본값 계승

| 토큰 | 값 | 사용 위치 |

| `--color-accent` / Accent | `#567354` | 보조 강조, 아이콘 |
| `--color-bg` / Background | `#F8F5EE` | 기본 페이지 배경 |

| `--color-muted` | `#676D63` | 보조 설명 |

규칙: 본문 대비비 최소 WCAG AA를 목표로 **실측 확인**. 사진 위 글자는 반투명 오버레이나 국소 그라데이션으로 대비 보장. 앱별 홍보 아트의 포인트 컬러는 별도 허용하며 웹 UI의 Primary 토큰을 임의로 바꾸지 않는다.

### 2.2 타이포

| 계층 | 기준 | 제약 |
|---|---|---|
| 히어로 헤드라인 | `Noto Serif KR`, 데스크톱 40–48px | 줄간격 1.3–1.42; 반응형 clamp 사용 |
| 섹션 제목 | `Noto Sans KR` 28–36px, 700–800 | 제목 레벨 의미 유지 |
| 카드 제목(UI) | `Noto Sans KR` 17–20px, 700–800 | 이미지 내부 텍스트와 중복 배치하지 않음 |
| 본문 | `Noto Sans KR` 15–16px, 400–500 | 줄간격 1.6–1.75 |
| 캡션·보조 | 12–14px, 400–600 | 모바일 12px 미만 지양 |
| 버튼·탭 | 14–15px, 600–700 | 긴 문구는 자연스럽게 줄바꿈/축약 |

글꼴은 기존 로딩(`Noto Sans KR`, `Noto Serif KR`) 재사용. 텍스트를 이미지로 통합하지 않는다. 단, 승인된 홍보 카드 아트 안의 제목/설명은 이미지 구성 요소로 유지한다.

### 2.3 간격·모서리·그림자

- **4px 기반, 8px 주단위**: `4, 8, 12, 16, 24, 32, 40, 48, 64, 80`px. 임의 13/19/27px은 실제 기하학적 필요가 있는 경우에만 예외.
- 패널 내부 padding: 모바일 16–20px, 데스크톱 24–32px.
- 일반 콘텐츠 간격: 16–24px; 서로 다른 섹션: 64–96px, 뷰포트/콘텐츠에 따라 조정.
- 큰 카드 `24px`, 중간 카드/패널 `20px`, 작은 UI `12–16px`; 완전 둥근 CTA `999px`.
- 공통 그림자는 기존 `--shadow-soft`, `--shadow-hover` 계승. 텍스트 가독성보다 강조 그림자가 눈에 띄면 실패.
- 아이콘: 동일한 Lucide 선 스타일 중심, 기본 20px/24px, 공식 앱 아이콘에는 Lucide 대용 사용 금지.

| 컴포넌트 | 기본 | hover/focus/disabled |

| Secondary Button | 높이 48px 이상, Paper 바탕/녹색 테두리, pill | 호버 대비 및 포커스 동일 |

### 2.5 반응형·정렬축

- **Breakpoints (v1.0 제안):** 넓은 PC `>=1200px`, 중간 `768–1199px`, 모바일 `<=767px`. 각 구간은 **같은 R5.4 디자인 언어**를 유지하면서 배치만 변경. 1050px 이하에서 R5.3 구형 폰 목업 히어로가 나타나는 것은 R5.4 최종 목표 아님.
- 공통 컨테이너: `max-width:1280px`; 데스크톱 좌우 gutter `40–48px`, 태블릿 `24–32px`, 모바일 `18–24px`. 로고, 히어로 타이틀, 버튼, 다음 섹션 제목의 **좌측 기준선 일치**.
- 각 구간의 실제 콘텐츠 너비·폰트/이미지 오버플로우는 QA에서 확정. 하드코딩 `transform: translateX(...)`로 정렬 보정 금지.
- 첫 히어로는 데스크톱에서 헤더·히어로·가치 바가 **한 뷰포트에 완결**되는 구성을 목표. 기준은 `100svh`, 하지만 화면 높이가 작을 때는 자동 콘텐츠 높이로 확장하여 내용 잘림 방지.

## 3. 코드 파일 운영 규칙

1. `public/styles/tokens.css`: 공통 컬러, spacing, radius, shadow, type/size 토큰의 **단일 기준**. 기존 변수명은 호환 유지.
2. `public/styles/base.css`: 전역 타입·body·컨테이너 정렬·포커스·기본 링크.
3. `public/styles/components.css`: 버튼, 카드 프레임, 헤더/CTA, 공통 상태.
4. `public/home-r54-*.css`: **히어로 레이아웃 전용**. 다른 파일과 중복되는 브랜드 컬러/컴포넌트 스타일 재정의 최소화.
5. `public/apps/*`: 앱 고유 UI만 남기고 공통 컴포넌트는 디자인 시스템의 토큰/클래스를 참조.

**마이그레이션 원칙**: 일괄 치환 금지. 비운영 브랜치에서 (a) 토큰 도입 → (b) 상단 히어로·헤더 → (c) 하단 섹션 → (d) 상세 페이지 순서로 이동; 단계별 시각·동작 회귀 테스트 후 확정.

## 4. 수용 기준 (Acceptance Criteria)

- [ ] PC 1440 / 1280 / 1200 / 1100 / 1024 및 820 / 768 / 430 / 390 / 360px에서 깨짐·가로 스크롤 없음.
- [ ] 같은 역할의 버튼은 색·높이·radius·아이콘 간격이 동일.
- [ ] 헤더 로고와 메인/하단 콘텐츠의 정렬축이 의도대로 일치.
- [ ] 앱 카드 3종은 기존 승인 에셋을 그대로 사용하며 이미지 왜곡/임의 크롭 없음.
- [ ] 포커스 가능/마우스·키보드 클릭 가능/읽기 대비 확인/`prefers-reduced-motion` 대응.
- [ ] 히어로·가치 바의 첫 화면 완결성과 작은 높이 뷰포트에서의 스크롤 허용을 함께 검증.
- [ ] 승인 전 `main` 병합 및 Cloudflare 프로덕션 배포 금지. 운영 R5.3 유지.

## 5. 추후 결정이 필요한 값

- 주요 breakpoint의 정확한 경계, 카드 컬럼 폭과 히어로의 최종 높이는 R5.4 실화면 비교 후 확정.
- 이 문서는 **표준화 작업의 출발점**이며 현재 운영 코드에 적용 완료되었다는 뜻이 아님.
