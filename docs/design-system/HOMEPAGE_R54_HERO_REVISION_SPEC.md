# Homepage R5.4 Hero — 레이아웃·정렬·반응형 수정지시서

- 상태: **구현 전 설계 초안 · 사용자 실화면 QA 피드백 반영**
- 기준일: 2026-11-08
- 대상: GitHub Issue #6 / Draft PR #7 (비운영 프리뷰)
- 안전: **`main`·Cloudflare 운영 R5.3 변경 금지**, 새 홍보 카드 이미지를 생성하거나 현재 원본을 덮어쓰지 않음.

## 0. 현재 확인된 문제

사용자가 전달한 두 화면을 기준으로 다음을 수정한다.

1. 넓은 PC에서는 R5.4 1+2 카드가 나오지만 중간 폭에서 구형 R5.3 폰 목업 히어로가 나옴 (현재 CSS에서 1050px 경계).
2. DZlog 메인 카드가 전체 화면에서 다소 작고 메인 카드 존재감 부족.
3. 우측 그리글과 MY LOCK의 **외곽 카드 높이/규격 통일** 필요.
4. MY LOCK 원본은 우측 슬롯보다 가로/세로 비율이 넓어 외곽/내용이 잘리거나 어색한 여백이 생겨 보임.
5. 헤더 로고·좌측 헤드라인·CTA 기준선이 지나치게 중앙에 치우쳐 보임.
6. 첫 화면의 히어로 + 하단 가치 바가 한 뷰포트 높이를 충분히 채우지 못함.

## 1. 변경하지 않는 것

- R5.3에서 승인한 자연광 공방 배경 이미지·브랜드 슬로건 문구·CTA 문구·가치 바 내용·각 앱 상세 페이지 주소.
- DZlog A / 그리글 C v3 / MY LOCK E 현재 이미지의 **내용 픽셀**. 우선 사이트 레이아웃만 수정. 원본 카드 리디자인은 별도 작업·검수로 분리.
- 공식 앱 아이콘, 실제 그리글 키보드 화면.

## 2. 수정 방침 및 권장 목표값 (초기 시뮬레이션 값, 최종 고정 아님)

| 항목 | 현재 | 제안 | 검수 기준 |
|---|---|---|---|
| 넓은 PC 히어로 | R5.4 1+2 | 유지 + 카드 존재감 확대 | 메인 카피와 균형 |
| 중간 폭(768–1199px) | 1050px 이하 구형 히어로 | **R5.4 동일 콘텐츠, 상단 텍스트 + 하단 1+2 카드** | 서로 다른 디자인으로 전환 금지 |
| 모바일(<=767px) | 구형 폰 목업 | R5.4 텍스트 + 단독 카드 세로 나열 | 읽기/터치 용이 |
| 카드 그룹 (>=1200px) | 예: 612×341px | **약 650×382px 후보** | DZlog가 5–12% 이상 선명하게 커짐 (실제 비교 필요) |
| 좌/우 카드 폭 (>=1200px) | 280 + 16 + 316 | **312 + 16 + 322px 후보** | DZlog 세로 비율 유지 |
| 우측 높이 | 1.2fr : 1fr | **1 : 1** | 두 카드 외곽 높이 정확히 동일 |
| 카드 모서리·간격 | 혼재 | radius 24px, gap 16px 기준 | 공통 UI System과 정합 |
| MY LOCK | 이미지 영역 불균형 | 웹 이미지 `contain` 유지 + 배경/슬롯 정렬 조정 | 얼굴/문구/폰 잘림 없어야 함 |
| 로고/텍스트 | 각기 다른 컨테이너 | 공통 `max-width:1280px` 그리드/좌측 기준축 | 임의 `translateX` 지양 |
| 히어로 높이 | clamp/고정 상한 혼재 | 가용 뷰포트 `100svh` 기반, 가치 바 포함 | 데스크톱 첫 화면 완결 |

**중요:** `650×382`는 레이아웃 탐색용 후보일 뿐. 가용 폭, 텍스트 안전영역, 화면 높이에 따라 보정. 오른쪽 카드 동일 높이를 우선하되 **현재 MY LOCK 이미지의 원본비(2.151)는 다른 카드(그리글 1.777)와 다름**. 두 장을 동일 비율로 늘리는 방식 대신, 카드 표면 배경에 비율 보존 이미지(`contain`)를 배치하고 필요 시 좌우 여백을 공통 톤으로 채운다. 앱 이미지 자체의 재생성/기능 내용 변경은 별도 승인.

## 3. 컴포넌트 구현 지시

### 3.1 통일된 PC/태블릿/모바일 DOM

- 두 히어로의 이중 유지/표시 전환을 없애 **R5.4 단일 히어로 콘텐츠**를 브레이크포인트에 따라 재배치하는 구조로 리팩터링.
- 구형 R5.3 폰 목업 코드를 직접 즉시 삭제하기보다는, 비운영 브랜치에서 R5.4 QA를 완료하고 회귀 검증 후 제거.
- `@media >=1200px`: 왼쪽 타이틀 + CTA, 오른쪽 1+2 카드. `768–1199px`: 카피 상단, 카드 그룹 하단. `<=767px`: 카피 후 카드 세로 열. 전 구간 R5.4 아트 사용.
- 각 카드 전체를 기존 URL (`/apps/dzlog/`, `/apps/grigle/`, `/apps/mylock/`)로 연결하고 시맨틱 링크/접근 가능한 이름 유지.

### 3.2 Card group

- 앱 카드 간 gap = 16px 기준. 우측 위·아래 카드의 **부모 박스 높이 완전 일치** (`grid-template-rows: repeat(2,minmax(0,1fr))`).
- DZlog 이미지는 좌측 카드 높이에 맞춰 보이도록 그룹 비율 조정. **원본 비율을 유지**하므로 먼저 그룹 폭과 높이를 공동 조정하고, `object-fit: cover`로 자르지 않음.
- 그리글·MY LOCK에는 모두 `object-fit: contain` 적용, 사용자가 보낸 스크린샷/공식 아이콘이 손상되면 실패. 이미지/컨테이너 비율 차이의 시각적 여백은 카드 배경과 동일한 단색/완만한 그라데이션으로 매끈하게 연결.
- 확대를 하더라도 화면 하단 가치 바와 겹치거나 뷰포트를 넘지 않아야 함.

### 3.3 헤더·카피/CTA 공통 정렬

- 헤더 로고, 히어로 제목/CTA, `#apps` 섹션 제목은 같은 컨테이너 토큰/수평 inset을 사용.
- 기존 `transform`을 이용한 단발성 x축 이동은 제거하고 `max-width`, `margin-inline:auto`, `padding-inline`로 정렬. 배경 사진의 구성은 기존 그대로.
- 첫 화면에서 왼쪽 시각축은 실제 화면을 보며 16–32px 범위에서 비교하되, 특정 화면폭만 하드코딩해 맞추지 않음.

### 3.4 히어로 전체 높이

- PC 화면의 상단 네비 헤더 높이를 변수로 관리. 히어로+가치 바의 총 높이를 `calc(100svh - header-height)`에 가깝게 조절.
- 가치 바가 현재 히어로 밖의 **겹침 배치**라면 레이아웃상 공간을 명시적으로 차지하도록 개선하여 화면 하단에 자연스럽게 정착. 1스크린 내 끝나되 768px 이하/세로 짧은 노트북에서는 자동으로 스크롤될 수 있어야 함.
- 히어로 콘텐츠를 가운데 배치하되 하단 가치 바와 카드 하단의 간섭/빈 공간이 과도하지 않게 분배.

## 4. 구현 순서

1. **화면 치수 기록/베이스라인**: 현재 프리뷰 PC 1650×900, 1440×900, 1280×800, 1100×800, 960×900 및 모바일 430×932, 390×844 각 화면에서 헤더/카드/가치 바 rect 수집.
2. **공통 토큰 적용**: `tokens.css`·`base.css`·`components.css`의 규격을 유지·확장하고 중복 override만 비운영 브랜치에서 조정.
3. **데스크톱 비율 정리**: 카드 그룹 확대, 우측 동일 높이, MY LOCK 비율 보존/배경 안전영역 보정. 원본 카드 이미지 수정 금지.
4. **중간/모바일 레이아웃 전환**: R5.4 단일 히어로 DOM을 스택 배치로 변경; 구형 폰 목업은 QA 종료 후 제거.
5. **정렬·높이 교정**: 로고/카피/CTA 왼쪽 기준선과 가치 바 하단 배치 검수.
6. **검증**: 정적 체크·빌드, 자동 브라우저 좌표/이미지 적재/오버플로/클릭/키보드 포커스 검수, 각 화면 폭 스크린샷 확인.
7. **사용자 검수**: PC/태블릿/모바일 실제 프리뷰 확인 후 수정 → 승인 → 별도 운영 배포 승인 게이트.

## 2026-11-08 · PC 실화면 피드백 추가 (Desktop Master v0.2)

- 사용자 선택 기준: **1440×900 PC의 1+2 카드 크기·시각적 비율**. 카드 그룹 680×400px(1440px 이상) 유지.
- 화면이 1920px 이상 커져도 콘텐츠 컨테이너를 중앙 1400px로 고정하지 않는다. **외곽 가터는 소폭만 변하고 좌측 카피와 우측 카드 사이의 빈 공간이 늘어나는 구조**를 우선한다.

- 해당 PC 변경은 화면 검수 전 시안이며 태블릿·모바일 디자인 변경을 포함하지 않는다.
