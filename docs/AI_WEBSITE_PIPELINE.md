# 두도지공방 홈페이지 — AI 협업·자동화 운영 기준

작성일: 2026-10-15
저장소: `Dudozi-workshop/dudozi-workshop-site`
작업 기준 브랜치: `feat/homepage-visual-r3-hifi`
운영 기준: `main` → Cloudflare Pages. 운영 사이트는 명시적인 배포 승인 전까지 변경 금지.

## 목적과 도구별 담당

하나의 디자인 기준을 여러 AI가 나눠 사용하는 방식이다. 동일 파일을 여러 에이전트가 동시에 수정하지 않는다.

| 역할 | 담당 | 산출물 | 실행 여부 |
| --- | --- | --- | --- |
| 작업 접수/규격/검수 | ChatGPT + GitHub Issue | 변경 범위, 고정 요소, 인수 조건 | GitHub 템플릿 제공 |
| 비교 시안 | Google Stitch | A/B 디자인, 변경 의도, 사용 자산 | 외부 계정에서 수동 시작 |
| 코드 반영 | Google Antigravity | 변경 diff, 브랜치 커밋, 로컬 QA | 외부 앱 설치·저장소 연결 필요 |
| 자동 QA | npm scripts + Playwright + CI | 빌드 결과, 브라우저 스크린샷, 오류 | 이미 있는 검사 재사용 |
| 비운영 검토 | Vercel | 고유 Preview URL, commit SHA | 요청 시 배포, 승인 전 운영 연결 금지 |
| 결정/운영 반영 | 사용자 | 디자인 승인, 배포 승인 | 반드시 명시적 승인 |
| 업무 이력 | GitHub Issue·PR | 진행 상태와 검수 증거 | GitHub 우선. Notion 자동동기화는 미구현 |

Stitch/Antigravity에 API 키나 사용자의 계정 로그인 정보가 필요하다면 본인 기기에서 인증한다.
API 키·쿠키·토큰을 Issue, PR, Git 커밋, AI 프롬프트에 기록하지 않는다.

## 상태 흐름

`제안 접수 → 디자인 생성 → 디자인 승인 대기 → 구현 중 → 정적 QA → 시각 QA → 프리뷰 승인 대기 → 병합·운영 배포 대기 → 완료`

예외:
- 디자인 미승인: 구현하지 않는다.
- QA 실패: 수정 후 다시 검수한다. 실패를 통과로 기록하지 않는다.
- GitHub Actions 러너가 작업 시작 전 종료(`runner_id=0`, `steps=[]`)한 경우: **환경 장애 / 미검증**으로 분리한다. 필요하면 별도 Vercel **비운영 빌드**에서 `npm run build` 결과를 확인한다. 이 빌드만으로 브라우저 시각 QA 통과를 주장하지 않는다.
- 브라우저 검사 불가: 수동 시각 검수 대기 상태 유지.
- 디자인 확정 및 배포 승인은 서로 별개다.

## 작업 1건의 입력 계약

1. 무엇을 개선할지와 이유.
2. 현재 스크린샷 또는 확인된 프리뷰 URL, 기준 commit SHA.
3. **수정 가능한 파일/영역**과 절대로 변경하면 안 되는 영역.
4. 고정 문구/이미지/규격, 실험 가능한 디자인 범위.
5. 검수 화면 너비·성공 조건.
6. 사용자가 승인해야 할 결정.

## 실제 처리 순서

### 1. 디자인 (Stitch)

- Issue 내용을 입력으로 사용한다.
- 승인된 Hero v4 구성은 그대로 유지하고 요청 영역만 A/B **2개 시안**을 만든다.
- 실제 앱 아이콘, 승인 이미지, 한국어 문구를 참고 자료로 제공한다.
- 렌더 이미지와 변경 요약, 사용한 이미지 출처·라이선스, 실제 스크린샷인지 콘셉트인지 구분하여 저장한다.
- **GitHub 코드는 이 단계에서 수정하지 않는다.**

### 2. 인간 승인

- A/B 시안을 비교하여 사용자에게 선택을 요청한다.
- 미승인 상태에서는 코드 변경·프리뷰 배포를 시작하지 않는다.
- 승인된 디자인 변경만 Issue 체크리스트와 확정 조건에 반영한다.

### 3. 구현 (Antigravity 또는 ChatGPT가 담당하는 단일 작성자)

- 작업 시작 시 원격 최신 소스를 읽고 해당 브랜치 HEAD를 확인한다.
- 선택된 Issue 하나당 한 작성자만 수정한다. 다른 에이전트가 동시에 편집하지 않도록 한다.
- 기존 CSS 토큰·공통 컴포넌트·실제 아이콘·로컬 이미지를 재사용한다.
- 수정 파일 목록과 변경 전/후 비교를 작성한다.
- 명시적 요청 없이 `main` 수정, PR 병합, 배포·도메인 설정·과금 작업을 하지 않는다.

### 4. 자동 검수

- `npm run check` 및 `npm run build` 통과.
- 정적 파일은 `npm run preview:local`로 열어 실제 브라우저에서 확인.
- Playwright 검사: `SITE_URL=http://127.0.0.1:4173 node scripts/visual-check.mjs` (Playwright·Chromium 설치 필요).
- PC **1440/1280/1100px**, 추가로 뷰포트가 세로로 긴 데스크톱 요청 모드에서 Hero 높이 제한 확인.
- 텍스트/카드 잘림·가로 스크롤·콘솔 오류·이미지 요청 실패가 없어야 한다.
- 수동 검수 항목: 버튼 연결, 제스처 표현의 정확성, 브랜드 통일성, 사진/자산 선명도, 변경하지 않는 페이지의 회귀.
- 자동 QA **통과**와 디자인 **사용자 승인**을 혼동하지 않는다.

### 5. 비운영 프리뷰 및 배포

- 일정 수정이 쌓였고 사용자가 검토를 요청한 시점에 Vercel **Preview** 1회 생성한다.
- Preview URL과 commit SHA, 변경 요약, 아직 검수되지 않은 항목을 함께 전달한다.
- 승인되지 않은 디자인은 되돌리거나 재작업한다.
- **운영 `main` 병합·Cloudflare Pages 배포는 별도 명시적 승인 후 진행**한다.

## 현재 구축 범위 및 한계

- 구현됨: 저장소 에이전트 지침, 작업 접수용 Issue 양식, PR 검수 양식, 그리글 시범 디자인 지시서, 기존 빌드 및 Playwright QA 재사용.
- 미연결: Stitch 계정/디자인 프로젝트, Antigravity 사용자 로컬 앱, Stitch↔Antigravity MCP 인증, Notion 자동 상태 동기화.
- 이 문서만으로 Stitch에서 자동 시안을 만들거나 Antigravity를 원격 조종하지는 않는다.
- 실제 연결 완료 여부는 시범 1회 수행하고 결과물을 확인한 뒤 기록한다.
